# AI Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "coming soon" AI chat tab with a real chat on the existing `v1/ai-chat` backend for users holding an AI chat permission, keeping the coming-soon page for everyone else.

**Architecture:** A new module `src/modules/AiChat` (api, types, hooks, components, screens, store, voice) with no manifest. `src/navigation/ai-chat-screen.tsx` picks the chat or the coming-soon page with `useCan()`. Server data goes through TanStack Query; the active session and the in-flight send are module UI state.

**Tech Stack:** Expo SDK 58, Expo Router, NativeWind classes via `@/shared/ui`, TanStack Query, zustand, `expo-document-picker` (via `core/files`), `expo-speech-recognition@58.0.x`, Jest + `@testing-library/react-native`.

**Spec:** `docs/superpowers/specs/2026-11-14-ai-chat-design.md`

## Global Constraints

- Permissions (any one): `read_aichat`, `read_all_aichat`, `approve_product_borrowing_as_product_manager`, `approve_product_borrowing_as_manager`, `process_product_borrowing`, `process_product_borrowing_as_logistic`.
- API paths under `apiClient` (which adds `/v1`): `/ai-chat/sessions`, `/ai-chat/sessions/{uuid}/messages`, `/ai-chat/progress/{trace}`, `/ai-chat/attachments/{uuid}`, `/ai-chat/messages/{uuid}/export`.
- Send: `message` ≤ 2000 chars, at most 3 files, extensions `pdf png jpg jpeg docx xlsx xls`, 10 MB per file, 5 MB per image (`png jpg jpeg`), `timeoutMs: 180_000`.
- Progress polling: 700 ms for the first 10 polls, then 1800 ms; only while a send is pending.
- UI from `@/shared/ui` and tokens only; text through `AppText`; class names only on RN primitives; touch targets ≥ 48.
- User bubble: `bg-primary-soft`, `ink` text, no border or shadow. AI reply: `bg-surface border border-border rounded-xl p-4`.
- No suggestion chips (`meta.suggestions` ignored). Server text shown as sent. App copy in English, sentence case, no exclamation marks.
- Voice: `lang: 'id-ID'`, interim results on, never auto-send.
- Never render server text as HTML.
- Install packages only with `npx expo install`. Never edit `ios/` or `android/`.
- **No git commits unless the user asks.** The working tree already holds uncommitted Price Approval work; each task ends with a checkpoint (tests + typecheck) instead.

## Review Focus

1. A send that takes 60–120 s → the pending card keeps showing progress; no timeout error before 180 s. (Task 5 test: `send passes timeoutMs 180000`.)
2. The user switches session, starts a new chat, or leaves the tab while a send is pending → the reply lands in the session it was sent to, and new chat/history are disabled while pending. (Task 9 test: header buttons disabled while pending.)
3. Send fails with timeout/network → the text is not lost and is not resent automatically. (Task 5 test: `unknown outcome refetches and keeps the draft`.)
4. Reply text containing `<b>`, `<script>` or a `|` inside a sentence → shown as plain text, not as a table or markup. (Task 3 tests.)
5. Mic on a build without the native module, on web without Web Speech, or with permission denied → mic hidden or a toast, never a crash. (Task 8 tests.)

**Files:**

**Interfaces:**

- Consumes: Task 2 api/keys, Task 4 store and `newTraceId`.
- Produces:

```ts
useChatSessions(enabled: boolean): UseQueryResult<ChatSession[]>;
useChatMessages(uuid: string | null): UseQueryResult<ChatHistory>;           // enabled only when uuid
useSendChatMessage(): { send(message: string, files: PickedFile[]): void; isPending: boolean };
useChatProgress(traceId: string | null): ProgressStep[];                    // [] when null
useDeleteChatSession(): UseMutationResult<void, AppError, string>;
useChatFile(): { downloadAttachment(a: ChatAttachment): void; exportMessage(messageUuid: string): void; busy: boolean };
```

`send` flow (one `useMutation`):

1. `traceId = newTraceId()`; `setPending({ sessionUuid: activeSessionUuid, message, files, traceId })`; `setFailedDraft(null)`.
2. `sessionUuid = activeSessionUuid ?? (await aiChatApi.createSession()).uuid`; if created, `setActiveSession(uuid)` and update `pending.sessionUuid`.
3. `await aiChatApi.send({ sessionUuid, message, files, traceId })`.
4. Success: `await invalidateQueries({ queryKey: aiChatKeys.messages(sessionUuid) })`, `invalidateQueries({ queryKey: aiChatKeys.sessions() })` (not awaited), then `setPending(null)`.
5. `validation`: `setPending(null)`, `setFailedDraft({ message, files })`, `toast.show({ tone: 'danger', message: error.message })`. Nothing refetched.
6. Any other error (outcome unknown): if a session uuid exists, `await invalidateQueries(messages(uuid))`; `setPending(null)`; `setFailedDraft({ message, files })`. Never resend.

`useChatProgress`: a `setTimeout` loop calling `aiChatApi.progress`, 700 ms for polls 1–10 then 1800 ms, ignoring errors, stopping on unmount or when `traceId` changes to `null`.

`useChatFile`: `getFile` then `shareFile(bytes, name, mime)`; export name `ai-chat-<yyyyMMdd-HHmm>.xlsx` with the xlsx MIME from `use-export-price-approvals.ts`; attachment MIME by extension, falling back to `application/octet-stream`; errors as a danger toast.

`useDeleteChatSession`: on success `invalidateQueries(sessions())`, `removeQueries(messages(uuid))`, and if active, `setActiveSession(null)`.
